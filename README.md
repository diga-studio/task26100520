# lineagetracker

内存中的版本血缘影响追踪库（Go）。只追踪初始化时指定的一个废弃版本；
顺序调用，不考虑并发与持久化。

## 接口

- `NewTracker(nodes, refs, deprecated)`：载入节点（版本/消费者）、引用与废弃版本，建立初始状态。
- `Rebind(refID, newTarget)`：改绑引用目标（空串表示停用，停用的引用可重新启用），
  返回本次新增受影响与不再受影响的消费者集合（替换前后两状态的集合差）。
- `Impact()`：返回当前全部受影响消费者集合。
- `Stats()` / `ResetStats()`：初始化之后的局部更新检查计数（节点/引用），用于核对工作量。

## 不变式

消费者受影响 ⟺ 从它沿当前有效引用能到达废弃版本。每个消费者至多出现一次；
`Impact` 与连续多次 `Rebind` 的结果始终一致。

## 正确性要点

为每个可达节点维护一条指向废弃版本的**凭证路径**（`parentRef`/`parentNode`），
全体凭证构成一棵以废弃版本为根的有向无环树（按挂接先后保证无环）。

- **删除引用 (u→t)**：若 u 的凭证不是这条引用（含 u 不可达、或凭证是同 owner→target
  的另一条重复引用），没有任何凭证路径经过它，直接返回。否则只有 u 的凭证子树 D
  可能失联：摘下 D 后做两阶段修复——D 中节点若有指向 D 外可达节点的引用则直接重新
  挂接（D 外节点的凭证不经过 D，仍然有效），再沿反向引用在 D 内扩散。修不好的节点
  真正不可达。环失去最后一条出路时，整环都在 D 内且无 D 外出口，必然全部退出，
  不会残留影响。
- **新增引用 (u→t)**：只有此前不可达的 u 且 t 可达时才产生变化，沿反向引用把新可达
  区域扩散出去；已可达的节点不受影响。
- **差集语义**：一次 Rebind 内的所有消费者状态翻转先记录原始状态，结束时与最终状态
  比较，暂时消失又恢复的消费者不会出现在返回值中。

## 时间代价

- 初始化：一次全图反向 BFS，O(N + M)。
- 单次 Rebind：只触及凭证子树及其关联引用，代价为 O(|D| + D 关联的引用数)，
  与无关分支的规模无关。测试 `TestLocalUpdatesIndependentOfBackgroundScale` 给出证据：
  30 节点/100 引用的小分支上改绑 1000 次，无论是否存在 20 万节点/100 万引用的背景分支，
  节点/引用检查计数完全相等（3205 / 2523），远低于一次全图扫描。

## 空间代价

常驻结构为节点表、引用表、正/反两个引用索引、凭证父指针与子节点表、受影响集合，
均为 O(N + M)；不预存任何节点对可达关系。

## 测试

```
go test ./...
```

覆盖：带消费者的环经唯一引用连到废弃版本的停用/恢复与永不连通的环；
菱形替代路径、重复引用、消费者多版本绑定、同一数据集两个版本的逐次差集核对；
随机小图上与独立全量计算核对的连续改绑序列（60 种子 × 150 步）；
以及上述 20 万节点/100 万引用背景下的局部性计数证明。
