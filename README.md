# lineage：内存中的版本血缘影响追踪

追踪**一个**初始化时指定的废弃版本，实时维护“沿当前有效引用能到达它”的消费者集合。
顺序调用，不考虑并发与持久化。

```go
tr, _ := lineage.NewTracker(nodes, refs, "urn:ds:dep:1")
added, removed, _ := tr.Rebind("ref-42", "urn:ds:other:3") // 改绑；"" 表示停用
affected := tr.Impact()                                    // 当前全部受影响消费者
```

## 数据语义

- 节点分版本与消费者，以完整 URN 区分；同一数据集的不同版本是不同节点。
- 引用有唯一 ID、固定 owner（版本或消费者）、可改绑的 target（只能是版本，空表示停用）。
- 允许重复引用（同 owner 同 target）、环、自引用与不连通部分。

## 实现思路（`tracker.go`）

每个节点维护 `dist`：到废弃版本的最短距离，`-1` 表示不可达。**消费者受影响
当且仅当 `dist` 有限**，这与“沿有效引用可达废弃版本”等价（最短路径必然有限）。

`Rebind(refID, newTarget)` 的增量更新：

1. 在旧图上从改绑引用的 owner 沿入边反向遍历，标记**祖先区域**（能到达 owner
   的节点）——只有这些节点的 `dist` 可能变化；区域外节点的可达子图不含这条
   引用，`dist` 必然不变。
2. 以 O(1) 摘挂把引用移到新 target 的入边链表（侵入式双链表，不随入度退化）。
3. 在新图上再标记一次祖先区域，取并集（改绑本身会改变“谁能到达 owner”）。
4. 只在区域内重算 `dist`：区域外邻居的现值作为边界，区域内跑多源 Dijkstra
   （单位权）。废弃版本恒为 0，作为边界不参与重算。
5. 比较区域节点的新旧 `dist`，有限↔不可达的跳变即消费者差集。

正确性要点：区域是“上游闭”的——区域外没有任何引用指向区域内（否则该节点
也能到达 owner，矛盾），因此区域外 `dist` 不受影响的归纳成立；区域内用边界值
做最短路重算，环与自引用由 Dijkstra 自然处理，失去最后通路后环内节点得不到
任何有限边界值，影响不会残留。差集来自替换前后两个稳定状态的对比，不存在
“过程中暂时消失又恢复”的误报；`Impact` 与连续 `Rebind` 共享同一份增量维护的
状态，结果必然一致。

## 代价

- **时间**：初始化是一次全图反向 Dijkstra，O((V+E) log V)。每次 `Rebind` 的
  工作量为 O((|A| + E_A) log |A|)，其中 A 是改绑点的祖先区域、E_A 是相关引用
  ——只取决于受影响局部，不触碰无关大分支（见下）。
- **空间**：邻接结构为每个节点/引用各存常数条链表指针，O(V+E)；不预存任何
  节点对可达关系。

## 测试（`go test ./...`）

- `tracker_test.go`：带消费者的环经唯一引用接废弃源，停用后整环退出、启用后
  恢复，环内改绑无扰动；永不连通的环始终不受影响。菱形替代路径 + 重复引用 +
  消费者多绑逐次改绑核对精确差集；同一数据集两个版本只影响引用废弃版本的一侧。
- `random_test.go`：40 组随机小图 × 60 步连续改绑，每步与独立全量 oracle
  （反向 BFS）核对 `Impact` 与差集。
- `scale_test.go`：≤30 节点 / 100 引用的小分支上改绑 1000 次，背景分支分别取
  2 万节点/10 万引用与 20 万节点/100 万引用，两分支只共享废弃源。两种规模下
  节点/引用检查计数**完全一致**（28239 / 75541），证明初始化后的局部更新
  工作量不随背景分支增长；每步差集与最终 `Impact` 均与 oracle 核对。
